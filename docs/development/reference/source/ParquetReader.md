## 1. What this file is

A dependency-free Parquet → JSONL converter that replaced a Python (pandas/pyarrow) subprocess, whose prebuilt wheels crashed with
`SIGILL` on CPUs without AVX2/AVX512. It contains its own Thrift compact-protocol decoder (for the footer and page headers), raw Snappy
decompressor, RLE/bit-packed hybrid decoder and PLAIN/dictionary value decoders, scoped to what HuggingFace `datasets-server` exports
use:

| Supported | Rejected (logged, returns −1) |
|---|---|
| Flat (non-nested, non-repeated) schemas; `REQUIRED`/`OPTIONAL` | Nested or repeated columns |
| `UNCOMPRESSED`, `SNAPPY` | Every other codec |
| DataPage V1, dictionary pages | DataPage V2 |
| `PLAIN`, `RLE_DICTIONARY`/`PLAIN_DICTIONARY` | Other encodings |
| `BYTE_ARRAY` (strings), `INT32`/`INT64`/`FLOAT`/`DOUBLE`/`BOOLEAN` (PLAIN) | `INT96`, `FIXED_LEN_BYTE_ARRAY`, encryption, external column chunks |

```text
convert_to_jsonl(parquet, jsonl, append):
  check PAR1 magic at both ends; read footer length; parse FileMetaData (Thrift)
  for every row group, every column chunk: dictionary page (optional), data pages (V1):
      decompress → definition levels (RLE/bit-packed) → values (PLAIN or dictionary indices) → cells
  validate value and row counts, then open the output and write one JSON object per row (schema order, null for absent)
```

Everything is decoded and validated before the output file is opened, so a rejected file leaves the output untouched, as the header
promises. Each part is held entirely in memory while converting.

## 2. Problems

The input is untrusted: any HuggingFace dataset an operator (or the dashboard) asks `registry_server` to fetch. The reader is careful
about buffer bounds (25,000 random mutations of the fixtures under ASan and UBSan produced **no memory-safety errors**), but it doesn't bound
the work and memory a file can demand.

### A 26-byte file hangs the reader, and a nested footer crashes the process (verified)

The Thrift decoder skips unknown fields with `skip_value()`, which has two gaps:
- **Unbounded list loops.** A list's declared size comes from a varint, and skipping a `BOOL` element consumes no bytes (in the compact
  protocol each list element should be one byte; the skipper treats it as the struct-field form, which has none). A footer with one unknown
  field holding a bool list of size ~2⁶² made `convert_to_jsonl()` **spin at 100% CPU until killed** (20 s timeout) on a **26-byte** file.
- **Unbounded recursion.** Nested structs recurse once per byte. A footer with 400,000 nested struct fields crashed the process with
  **SIGSEGV (stack overflow)**.

In `registry_server`, the first ties up a request thread forever and the second **kills the whole daemon** (a segfault can't be caught),
for a malicious or merely corrupt dataset. Same class as TD-309 (a `DataFetcher` input crashing `registry_server`).

### Declared sizes are trusted for allocations (verified in part)

Sizes read from the file are used for allocations before being checked against the data actually present: page `compressed_page_size`
(a negative `int32` becomes a huge `size_t`), Snappy's declared uncompressed length (`reserve()`), a page's `num_values` (`int32`, cast to
`size_t`, then `def_levels.assign(…)`/`reserve(…)`), and the row group's `num_rows`. The fuzzer hit **62 escaped `std::length_error`
exceptions** (from `vector::reserve` and `string::resize`). `httplib` turns an escaped exception into HTTP 500, so these don't crash the
server, but nothing in `ParquetReader` or `DataFetcher` catches them, so partially downloaded parts aren't cleaned up. By inspection,
a plausible size is worse than an absurd one: a page claiming 2³¹ values in a `REQUIRED` column allocates and fills **8 GB** of
definition levels from a few bytes (and one RLE run can expand to `num_values` entries), which would push the host toward the OOM killer.

### Smaller items (by inspection)

- **Exceptions vs. the contract.** The header promises "returns −1 on any unsupported/corrupt input"; allocation failures throw instead.
- **Whole part in memory.** All rows of a part are decoded before writing; very large parts cost their full decoded size in RAM.
- **Tests**: the only end-to-end comparison with pyarrow (`DISABLED_TinyStoriesPartsMatchPythonReference`) is disabled; there are no
  malformed-input tests beyond a single "corrupt file" case.

## Addendum (October 24, 2026): bounded Thrift skipping (TD-470)

- **List sizes:** `read_list_header()` rejects a list size larger than the bytes left.
- **Bool elements:** `skip_list_element()` consumes the byte a bool element takes inside a list.
- **Depth:** `skip_value()` refuses nesting beyond 64 levels.

A 24-byte file with a 2⁶²-element bool list (which looped forever) and a footer with 400,000 nested structs (which segfaulted) now
make `convert_to_jsonl()` return −1. Tests: `HugeBoolListInFooterFailsInsteadOfLooping`, `DeeplyNestedFooterFailsInsteadOfCrashing`.
